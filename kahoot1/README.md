# MangosGo

เกมตอบคำถามเรียลไทม์ที่ทำเองทั้งระบบ — สร้างชุดคำถาม เปิดจอใหญ่ ผู้เล่นเข้าด้วย PIN
รองรับผู้เล่นพร้อมกัน 50 คนต่อห้อง มี 5 โหมดการเล่น และใช้ได้ทั้งภาษาไทยและอังกฤษ

เซิร์ฟเวอร์เป็น **Node ไฟล์เดียว** (`server.js`) เสิร์ฟทั้งหน้าเว็บและ WebSocket บนพอร์ตเดียวกัน
ไม่มี framework ไม่มี build step แก้ไฟล์แล้วรีเฟรชเบราว์เซอร์ได้เลย

## เริ่มใช้งานใน 3 นาที

**ต้องมี Node 22.5 ขึ้นไป** (ใช้ `node:sqlite` ที่ติดมากับ Node เลยไม่ต้องลงฐานข้อมูลแยก)
เช็คเวอร์ชันด้วย `node -v`

```bash
npm install
```

```bash
npm start
```

เปิด <http://localhost:8000> — เท่านี้เสร็จ

เปลี่ยนพอร์ตได้ด้วย `PORT=8100 npm start`

### ให้คนอื่นในวง Wi-Fi เดียวกันเข้าเล่น

หาไอพีเครื่องตัวเองก่อน (Windows ใช้ `ipconfig` ดูค่า IPv4 เช่น `192.168.1.50`)
แล้วให้ผู้เล่นเปิด `http://192.168.1.50:8000` จากมือถือ เครื่องต้องอยู่ Wi-Fi วงเดียวกัน

## ใช้งานยังไง

มี 3 บทบาท ใช้คนละหน้า

| ใคร | เปิดหน้าไหน | ทำอะไร |
| --- | --- | --- |
| **คนสร้างคำถาม** | `/Make/` | พิมพ์คำถาม ใส่รูป เลือกคำตอบที่ถูก กด Save ได้ PIN |
| **จอใหญ่ (host)** | `/host/?pin=XXXXXX` | โชว์ PIN เลือกโหมด กด Start แล้วฉายคำถามให้ทุกคนดู |
| **ผู้เล่น** | `/page/` | ใส่ PIN → ตั้งชื่อ + เลือกอวตาร → ตอบคำถามบนมือถือ |

### ลำดับการเล่น

1. สร้างชุดคำถามที่ `/Make/` กด **Save** จะได้ PIN 6 หลัก
2. เปิด `/host/?pin=PIN` บนจอใหญ่หรือโปรเจกเตอร์
3. ผู้เล่นเปิด `/page/` ใส่ PIN ตั้งชื่อเล่น เลือกสีนักบินอวกาศ
4. host เลือกโหมดเกม แล้วกด **Start**
5. **จบแค่นั้น** — หลังจากนี้เกมเดินเองจนจบ host ไม่ต้องกดอะไรอีก
   หมดเวลาแต่ละข้อ → เฉลย → อันดับ → ข้อถัดไปอัตโนมัติ → แท่นรับรางวัลตอนจบ

## ระบบทำงานยังไง

### หลักการเดียวที่ต้องจำ

> **เซิร์ฟเวอร์เป็นคนตัดสินทุกอย่าง หน้าเว็บเป็นแค่จอแสดงผล**

คำตอบที่ถูก คะแนน เวลาที่เหลือ ลำดับคำถาม ใครตกรอบ — คิดที่เซิร์ฟเวอร์ทั้งหมด
หน้าเว็บทำแค่วาดสิ่งที่ได้รับกับส่งคำตอบกลับไป แก้โค้ดฝั่งหน้าเว็บโกงคะแนนไม่ได้

ไม่มีการ poll เลย ทุกอย่างถูก **push** ผ่าน WebSocket

### สถานะเกมอยู่ในหน่วยความจำ

`server.js` เก็บห้องที่กำลังเล่นไว้ใน `Map` ชื่อ `rooms` โดยใช้ PIN เป็นกุญแจ
แต่ละห้องมีสถานะ ผู้เล่น คะแนน และตัวจับเวลาของตัวเอง เป็นอิสระจากห้องอื่น
เปิดหลายห้องพร้อมกันได้ไม่จำกัด (จำกัดแค่ 50 คนต่อห้อง)

ส่วน SQLite ใช้เก็บแค่ **ชุดคำถามจากหน้า Make** กับบันทึกผลย้อนหลัง ไม่ได้ใช้ระหว่างเล่น

### ข้อความที่วิ่งไปมา

**หน้าเว็บ → เซิร์ฟเวอร์**

| ข้อความ | ใครส่ง | ผล |
| --- | --- | --- |
| `HOST_ROOM {pin}` | จอ host | โหลดชุดคำถามเข้าห้อง สมัครเป็น host (เปิดหลายจอพร้อมกันได้) |
| `JOIN_ROOM {pin, name, avatar, playerId?}` | ผู้เล่น | เข้าห้อง มี `playerId` = คนเดิมต่อกลับ |
| `START_GAME {mode}` | host | เริ่มเกมด้วยโหมดที่เลือก |
| `ANSWER {answer}` | ผู้เล่น | ส่งคำตอบ ตอบได้ครั้งเดียวต่อข้อ |

**เซิร์ฟเวอร์ → หน้าเว็บ**

| ข้อความ | ความหมาย |
| --- | --- |
| `HOST_READY` | ยืนยันว่าคุมห้องนี้แล้ว พร้อมรายการโหมดและจำนวนข้อ |
| `JOINED` | ยืนยันการเข้าห้อง พร้อม id คะแนน และอวตาร |
| `ROOM_STATE` | รายชื่อผู้เล่นและสถานะห้องล่าสุด |
| `QUESTION` | คำถาม ตัวเลือก รูป และเวลาที่เหลือจริง (ms) |
| `ANSWER_ACCEPTED` | รับคำตอบแล้ว **แต่ยังไม่บอกว่าถูกหรือผิด** |
| `ANSWER_RESULT` | ผลของผู้เล่นคนนั้น ส่งตอนหมดเวลาเท่านั้น |
| `ANSWER_COUNT` | จำนวนคนที่ตอบแล้ว (ส่งให้จอ host อย่างเดียว) |
| `LEADERBOARD` | เฉลย จำนวนคนที่เลือกแต่ละข้อ อันดับ และเหลืออีกกี่ ms จะไปข้อถัดไป |
| `FINAL` | คะแนนสรุปตอนจบเกม |
| `ERROR` | ปัญหาต่าง ๆ ส่งมาเป็น `code` ให้หน้าเว็บแปลเอง |

### กติกาที่เซิร์ฟเวอร์คุม

- **คะแนน** ตอบถูกได้ `100 + 900 × (เวลาที่เหลือ ÷ เวลาทั้งหมด)` ตอบเร็วได้มากกว่า
- **โบนัสตอบถูกติดกัน** ข้อที่ 2 ของ streak +100 ไล่ขึ้นทีละ 100 จนตันที่ +500
  ตอบผิดหรือไม่ตอบ streak ขาดทันที
- **กั๊กผลไว้จนหมดเวลา** ตอบแล้วขึ้นแค่ "รอคนอื่น" ทุกคนรู้ผลพร้อมกัน ไม่มีใครรู้ก่อนใคร
- **เดินครบเวลาเสมอ** ต่อให้ทุกคนตอบครบก็ไม่ตัดจบก่อน
  (อยากให้ตัดจบทันทีที่ทุกคนตอบครบ เปลี่ยน `END_WHEN_ALL_ANSWERED = true`)
- **ต่อกลับได้ใน 15 วินาที** ด้วย `playerId` ที่เก็บใน `sessionStorage` คะแนนกับ streak ไม่หาย
  ต่อกลับกลางข้อจะได้สถานะคำถามปัจจุบันทันที
- **ห้องละไม่เกิน 50 คน** คนที่ต่อกลับไม่ติดลิมิตนี้ ไม่งั้นคนที่เล่นอยู่จะโดนล็อกออกจากเกมตัวเอง

### รูปในคำถาม

หน้า Make ส่งรูปมาเป็น data URL แต่เซิร์ฟเวอร์ไม่เก็บไว้แบบนั้น — มันเขียนลง `uploads/`
โดยตั้งชื่อไฟล์เป็น hash ของเนื้อไฟล์ แล้วเก็บในชุดคำถามแค่ `/uploads/<hash>.png`

**ทำไมต้องทำแบบนี้:** ถ้าฝังรูปไว้ในชุดคำถาม รูปก้อนเดิมจะถูกยิงไปกับ `QUESTION`
ให้ผู้เล่นทุกคนทุกครั้งที่ขึ้นคำถาม ห้อง 50 คนกับรูป 500 KB = **25 MB ต่อข้อเดียว**
พอส่งแค่ URL ข้อความเหลือ ~0.2 KB ต่อคน และเบราว์เซอร์แคชรูปไว้ยาว

หน้าล็อบบี้ยังโหลดรูปทั้งชุดดักไว้ตั้งแต่ตอนรอ host กด Start พอเกมเริ่มรูปจึงขึ้นทันที

ชุดคำถามเก่าที่ยังฝัง data URL อยู่จะถูกแปลงให้อัตโนมัติครั้งแรกที่เปิดห้อง

## โหมดเกม

เลือกก่อนกด Start บนจอ host ทุกโหมดใช้เอนจินเดียวกัน ต่างกันแค่กติกา

| โหมด | กติกา |
| --- | --- |
| 🎯 **คลาสสิก** | ตอบเร็วได้คะแนนเยอะ + โบนัสตอบถูกติดกัน (ค่าเริ่มต้น) |
| 🎓 **แม่นยำ** | ตอบถูกได้ 1000 เท่ากันหมด ไม่วัดความเร็ว คนคิดช้าไม่เสียเปรียบ |
| 💀 **ตกรอบ** | ตอบผิดหรือไม่ทันตอบ = ตกรอบ ดูต่อได้แต่ตอบไม่ได้ เหลือคนเดียวจบเกม |
| 🕳️ **หนีหลุมดำ** | นักบินวิ่งหนีหลุมดำ ตอบถูก +1 ระยะ (ตอบไวได้ +2) ตอบไม่ได้ −1 ระยะหมดคือโดนดูด |
| ⚡ **เร่งรีบ** | บีบทุกข้อเหลือ 5 วิ ไม่สนเวลาที่ตั้งไว้ในสไลด์ |

### Black Hole Run ทำงานยังไง

ฉากไล่ล่าอยู่บน **จอ host เท่านั้น** มือถือผู้เล่นมีแค่ปุ่มตอบ
โหมดนี้จอใหญ่ไม่ขึ้นคำถามเลย โชว์ฉากค้างไว้ตลอด นักบินทุกคนอยู่ในเวทีเดียวกัน
หลุมดำอยู่ซ้ายสุด ใครอยู่ขวาสุดคือนำ มีชื่อกำกับทุกตัว

เริ่มที่ระยะ 5 สูงสุด 10 แตะ 0 เมื่อไหร่โดนดูด ทุกคนโดนดูดหมดเกมจบทันที

## สองภาษา

ทุกหน้ามีปุ่ม 🌐 สลับ **ไทย ⇄ EN** เปลี่ยนทันทีทั้งหน้าโดยไม่ต้องรีเฟรช
ภาษาที่เลือกจำไว้ใน `localStorage` เปิดหน้าไหนต่อก็ได้ภาษาเดิม ค่าเริ่มต้นเป็นไทย

พจนานุกรมอยู่ที่ [`shared/i18n.js`](shared/i18n.js) ที่เดียว มี 120 คีย์ครบทั้งสองภาษา

| ข้อความอยู่ที่ไหน | แปลยังไง |
| --- | --- |
| ข้อความคงที่ใน HTML | ใส่ `data-i18n="key"` |
| placeholder / title | เพิ่ม `data-i18n-attr="placeholder"` |
| ชื่อแท็บเบราว์เซอร์ | `data-i18n-title` ที่แท็ก `<html>` |
| ข้อความที่ JS สร้างเอง | `KG.i18n.t('key', { ตัวแปร })` |
| ข้อความที่วาดครั้งเดียวแล้วค้าง | ลงทะเบียน `KG.i18n.onChange(...)` ให้วาดใหม่ |

**ข้อความจากเซิร์ฟเวอร์ไม่ได้ส่งมาเป็นประโยค** เพราะจะสลับภาษาไม่ได้หลังส่งไปแล้ว
`ERROR` ส่ง `code` มาให้หน้าเว็บแปลเอง ส่วนชื่อโหมดเก็บเป็น `{ th, en }` ทั้งคู่แล้วส่งไปทั้งก้อน

ชื่อชุดคำถามกับตัวคำถามที่ครูพิมพ์เองไม่ได้แปล แสดงตามที่พิมพ์มา

## อยากแก้อะไร ไปดูตรงไหน

| อยากทำ | แก้ที่ |
| --- | --- |
| เพิ่มโหมดเกมใหม่ | `MODES` ใน `server.js` — เติม object ใหม่ที่เดียว การ์ดบนจอ host โผล่เอง |
| เปลี่ยนสูตรคะแนน | ตัวจัดการ `ANSWER` ใน `server.js` |
| เปลี่ยนเวลาค้างหน้าเฉลย | `LEADERBOARD_HOLD_MS` (ตอนนี้ 6 วิ) |
| เปลี่ยนจำนวนคนสูงสุด | `MAX_PLAYERS_PER_ROOM` |
| เพิ่ม/แก้คำแปล | `shared/i18n.js` |
| เพิ่มสีอวตาร | `AVATARS` ใน `server.js` (หน้าเลือกดึงจาก `GET /api/avatars`) |
| แก้เสียง | `shared/sound.js` — สังเคราะห์ด้วย Web Audio ไม่มีไฟล์เสียงให้เปลี่ยน |
| แก้หน้าตาจอ host | `host/host.css` — สลับหน้าตาด้วยคลาสที่ `<body>` (ดูตารางล่าง) |

### คลาสที่ `<body>` ของจอ host

| คลาส | ช่วง | หน้าตา |
| --- | --- | --- |
| (ไม่มี) | ล็อบบี้ | PIN ตัวใหญ่ + การ์ดเลือกโหมด + ปุ่ม Start |
| `is-playing is-question` | กำลังถาม | ซ่อนของในล็อบบี้ เหลือคำถามกับตัวเลือกเต็มจอ |
| `is-playing is-reveal` | เฉลย | เพิ่มอันดับและจำนวนคนที่เลือกแต่ละข้อ |
| `is-run` | โหมดหลุมดำ | ซ่อนคำถาม เหลือแต่ฉากไล่ล่า |
| `is-final` | จบเกม | แท่นรับรางวัลเต็มจอ |

### ตัวเลือกของโหมด (ใส่ใน `MODES`)

`flatScore` / `noSpeed` (ไม่คิดคะแนนตามเวลา) · `noStreak` (ปิดโบนัส) · `duration` (บังคับเวลาต่อข้อ)
`eliminate` (ตอบผิดตกรอบ) · `blackhole` (ระยะหนีหลุมดำ) · `endWhenAlive` (เหลือกี่คนถึงจบเกม)

## ข้อจำกัดที่ต้องรู้ก่อนใช้จริง

**ใช้ในห้องเรียนหรือวง Wi-Fi เดียวกันได้เลย** ทดสอบแล้วว่ารองรับ 50 คนพร้อมกัน
หลุดแล้วต่อกลับได้ หลายห้องพร้อมกันไม่กวนกัน และยิงข้อมูลพัง ๆ เข้าไปเซิร์ฟเวอร์ไม่ล้ม

**แต่ยังไม่ควรเอาขึ้นอินเทอร์เน็ต** เพราะ:

1. **ไม่มีการยืนยันตัวตนเลย** ใครรู้ PIN ก็เปิด `/host/?pin=xxx` แล้วกด Start ได้
   ในห้องเรียนไม่เป็นไร แต่บนเน็ตใครก็ป่วนเกมได้
2. **รีสตาร์ทเซิร์ฟเวอร์ = เกมที่ค้างอยู่หายหมด** เพราะสถานะอยู่ในหน่วยความจำล้วน
3. **PIN เล่นซ้ำไม่ได้ทันที** จบเกมแล้วกด Start ซ้ำไม่มีผล ต้องให้ทุกคนปิดแท็บแล้วรอ 15 วิ
   ห้องถึงจะรีเซ็ต หรือไปสร้าง PIN ใหม่ ← เจอบ่อยสุดเวลาสอนหลายห้องติดกัน
4. **ไม่มี HTTPS/wss** เบราว์เซอร์สมัยใหม่จะบล็อกเมื่ออยู่บนโดเมนจริง
5. **ใครก็สร้างชุดคำถามได้ไม่จำกัด** `POST /api/quizzes` เปิดโล่ง

### เรื่องเล็กที่ควรรู้

- `correctIndex` ที่เกินจำนวนตัวเลือก (ยิง API ตรงเท่านั้น หน้า Make สร้างไม่ได้)
  จะบันทึกผ่านแบบเงียบ ๆ แล้วข้อนั้นจะไม่มีใครตอบถูกได้เลย
- โฟลเดอร์ `uploads/` ต้องไปพร้อมกับ `mangosgo.sqlite3` เสมอ ย้ายเครื่องแล้วลืมเอาไปรูปจะหาย
- ฐานข้อมูลตอนนี้มี 118 ชุดคำถาม ส่วนใหญ่เป็นชุดที่สร้างตอนทดสอบ ลบทิ้งได้

## ฐานข้อมูล

`mangosgo.sqlite3` มี 3 ตาราง

| ตาราง | เก็บอะไร |
| --- | --- |
| `quizzes` | ชุดคำถาม (PIN, ชื่อ, สไลด์ทั้งหมดเป็น JSON, สถานะ) |
| `players` | รายชื่อคนที่เคยเข้าแต่ละ PIN |
| `answers` | คำตอบรายข้อของแต่ละคน พร้อมคะแนนที่ได้ |

การเขียนระหว่างเกมถูกครอบด้วย try/catch ไว้หมด — ถ้าเขียนไม่ได้ เกมที่เล่นอยู่ต้องไม่ล้ม

## REST endpoint

| endpoint | ใช้ทำอะไร |
| --- | --- |
| `POST /api/quizzes` | หน้า Make บันทึกชุดคำถาม แล้วได้ PIN กลับไป |
| `POST /api/join` | หน้าใส่ PIN ตรวจว่ามีเกมนี้จริงก่อนพาไปล็อบบี้ |
| `GET /api/avatars` | รายการสีอวตารสำหรับหน้าเลือก |
